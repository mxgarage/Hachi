# Hachi 体验走查指南（给测试的人）

目的：在一台真实的 Mac 上，用大约 15 分钟确认菜单和提醒的表现。逐项对应 `docs/ux-checklist.md`（条目编号相同）。这不是安全测试，也不替代维护者的正式签收。

准备：下载预发布里的 zip，解压；第一次**右键 → 打开** `Hachi.app`（ad-hoc 签名，未公证）。CI 渲染的截图在对应提交的 `hachi-<sha>` 产物里（`acceptance/ux/index.html`），可以用来对照。

## 1. 启动和菜单栏（5 分钟）

| 步骤 | 应该看到 | 条目 |
|---|---|---|
| 打开应用 | 没有 Dock 图标、没有窗口，菜单栏出现侧面的小狗 | UX-01, 02 |
| 看尾巴 | 一直平滑摇动；开启“减少动态效果”后一秒内静止，关闭后恢复 | UX-03 |
| 鼠标悬停 | 提示“Hachi · 观察模式（不拦截）”；VoiceOver 读作“Hachi 小八” | UX-04 |
| 点图标 | 前三行是灰色的，点了没有反应 | UX-05 |
| 关/开 Wi-Fi | “系统网络”行从“等待状态”变成“可用（不是出口验证）”；断网后变“不可用或待建立”，恢复后改回 | UX-06 |
| 通读所有文字 | 没有任何一处说流量“已保护/已拦截/已路由” | UX-07 |

## 2. 出口检查（5 分钟）

1. 没装 `claude-safe` 时点“检查 Claude 出口”：应弹出“Claude：预检未通过”，说明无法运行入口；不卡死（UX-08）。
2. 用文档里的示例入口（UX-10 的命令，不会覆盖已有文件）分别做“通过”和“失败”：
   - 通过：标题“预检通过”，显示输出，末尾有“这只是预检……未覆盖”的说明。
   - 失败：标题“预检未通过”，除了输出，还应说明 Hachi 只转述输出、IP 一致也可能未通过。想看到贴近真实的情形，可以让失败入口多输出一行合成数据，例如 `echo "IP=203.0.113.10 expected=203.0.113.10 observed_route=NOT OBSERVED"`（放在 `exit 1` 之前）；真实脚本的输出格式不在本仓库里，提示只是固定文案。
   - 检查中：对应菜单行变灰，悬停提示“Hachi · 预检中”，结束后恢复（UX-09）。
3. 提醒应置于最前，按回车或 OK 关闭，焦点回到之前的应用（UX-11）。
4. 做完删除示例入口：`rm ~/.local/bin/claude-safe`（若原本就有真实入口，先挪开、做完再放回）。

## 3. 外观和退出（3 分钟）

- 浅色、深色、开启“增强对比度”下，菜单和提醒都清晰，没有被截断（UX-12）。
- 菜单里的“退出”或 ⌘Q 能退出，图标消失，活动监视器里没有残留进程（UX-13）。

## 怎么记录

每项写 通过 / 不通过 + 一句话现象（最好带截图）。不通过的开 issue，标题里带条目编号。正式签收仍由维护者按 `evidence/README.md` 写 `evidence/G6-ux-signoff.json`。
