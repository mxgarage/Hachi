# 手机出口对照：扫码配对交互设计

状态：设计稿，未实现。维护者 2026-11-25 选定“扫码配对”方案。

## 1. 目的和边界

很多人在 Mac 上浏览，在手机上订阅或付款（App Store、Google Play、平台 App 内购）。两台设备的网络出口可能不在同一个国家或地区，用户自己往往不知道。这个功能只做一件事：**让用户同时看到“这台 Mac 现在从哪里出去”和“手机现在从哪里出去”，由用户自己对照。**

边界（与 [AGENTS.md](../AGENTS.md) 的范围条款一致）：

- 只提醒，不拦截，不改任何网络设置，不替用户切换出口。
- 不判断出口“对不对”、能不能让账号或付款通过。出口位置不等于服务资格，平台按真实所在地和账号信息判断（证据包 A1、O2）。
- 不对不一致的情况给出任何绕开地区限制或平台风控的建议。
- 只显示到国家或地区一级，不显示城市、运营商或 IP。

## 2. 什么时候出现

| 时机 | 行为 | 说明 |
|---|---|---|
| 用户主动 | 菜单新增一项“对照手机出口…”，随时可用 | 主入口，永远可用 |
| 订阅或付款前 | 菜单里的“检查 Claude 出口 / 检查 Codex 出口”结果弹窗下方，加一个“付款前对照手机出口”按钮 | Hachi 是菜单栏应用，看不到浏览器里打开了什么页面，所以不做“自动识别付款页”。这个入口靠用户在付款前顺手点一下 |
| 网络变化 | `NWPathMonitor` 报告接口切换或路径从不可用恢复为可用后，菜单栏图标旁出现一个小圆点，菜单顶部出现“网络变了，要对照手机出口吗？” | 不弹窗、不发系统通知、不自动出二维码。同一网络 10 分钟内只提示一次；用户点“这次不用”后，到下一次网络变化前不再提示 |

二维码只在用户点了上面某个入口之后才生成和显示。Hachi 不在后台定时让手机去查。

## 3. 主流程

1. 用户点“对照手机出口…”。
2. Mac 先查自己的出口地区（见第 6 节依赖），然后弹出窗口：左边是二维码，右边是“这台 Mac：<地区>”。
3. 用户用手机相机扫码，手机浏览器打开检查页。
4. 检查页只显示一行大字“这部手机：<地区>”，下面一行小字是隐私说明（第 5 节），再下面是“回到 Mac 上对照”。
5. 用户回到 Mac，窗口里有三个按钮：**“一致”**、**“不一致”**、**“扫不了，手动选”**。
6. 选“一致”：关闭窗口，菜单里记一行“上次对照：一致（<时间>）”，只存在内存里，退出即清空。
7. 选“不一致”：进入第 4 节的提醒。

第一版里手机**不把结果传回 Mac**，由用户自己看两边的地区并点按钮。这样二维码里不需要任何会话标识，Mac 和检查页之间也没有连接。以后如果要自动对照，另开 issue 讨论（第 7 节）。

二维码内容只是固定的检查页地址，不带设备、用户或会话参数。二维码 5 分钟后变灰，显示“已过期，点一下重新生成”，避免用户扫一张很久以前截下来的图。

## 4. 文案

### Mac 窗口

- 标题：对照手机出口
- 说明：用手机相机扫这个码，手机会打开一个页面，显示手机现在的网络出口在哪个国家或地区。看完回来点下面的按钮。
- Mac 侧：这台 Mac：日本（JP）
- Mac 侧查询失败：这台 Mac：暂时查不到（不影响你继续对照手机）
- 按钮：一致 / 不一致 / 扫不了，手动选
- 底部小字：只看国家或地区。Hachi 不记录 IP，也不把手机的结果传回这台 Mac。

### 手机检查页

- 主文字：这部手机：日本（JP）
- 查询失败：暂时查不到这部手机的出口。可以关掉 Wi‑Fi 或切换网络后刷新一次。
- 隐私说明：这个页面只读取你的网络出口所在的国家或地区，不记录 IP，不用 Cookie，不收集其他信息。只有你扫码打开时才会查询。
- 底部：回到 Mac 上对照

### 不一致时的提醒（Mac）

- 标题：两台设备的网络出口不在同一个地区
- 正文：
  > 这台 Mac：日本（JP）
  > 这部手机：美国（US）
  >
  > 这只是提醒。Hachi 不判断哪一个“对”，也不会帮你修改网络。
  >
  > 如果你接下来要订阅或付款，可以先确认：
  > · 应用商店账号设置里的国家或地区，是不是你实际所在的地区；
  > · 付款方式的账单地址和这个地区是否一致。
  >
  > 拿不准的话，请直接联系应用商店或对应服务的客服确认。
- 按钮：知道了

提醒里不出现“切换节点”“换成某地出口”“关掉/打开 VPN 再付款”之类的建议，也不出现“这样更安全”“不会被封”之类的承诺。

## 5. 手动兜底

扫不了码（没有相机权限、手机不在身边、公司网络拦了检查页）时，用户点“扫不了，手动选”：

- 说明：在手机上打开任意一个显示 IP 所在地的页面，或者看手机的应用商店地区设置，然后在这里选手机的地区。
- 控件：国家或地区下拉列表（ISO 3166 列表，默认空），以及“我不确定”。
- 选了地区：和 Mac 侧对照，一致就照第 3 节第 6 步，不一致就显示第 4 节的提醒，标题改为“你选的手机地区和这台 Mac 的出口不一致”。
- 选“我不确定”：只显示一句“没关系。付款前如果拿不准，请联系应用商店或对应服务的客服确认。”，然后关闭。

手动选的地区同样只存在内存里，不写磁盘。

## 6. 隐私说明和实现约束

对用户的承诺（同时写在手机检查页上）：

- 检查页只读取出口所在的国家或地区。
- 不记录 IP，不用 Cookie、本地存储或第三方统计脚本，不收集设备型号、浏览器指纹或位置权限。
- 只有用户扫码打开页面时才查询，Hachi 不会在后台让手机发请求。

为了让这些承诺成立，实现时要满足（写给以后的实现 PR，也作为评审清单）：

- 任何网页服务器都会在请求里看到访问者的 IP，所以“不记录”必须是服务端配置做到的：访问日志关闭或去掉 IP 字段，查完地区后立刻丢弃 IP，响应里只返回国家或地区代码。
- 检查页静态、无第三方资源，响应加 `Cache-Control: no-store`。
- Mac 侧的出口查询同样只保留地区代码，不写日志，不写磁盘。现在的 Hachi 只观察网络路径是否可用，没有出口 IP 查询（README 写明“网络可用不等于验证过的出口 IP”），所以 Mac 侧查询是这个功能的前置依赖，要单独设计。
- 仓库里不放检查页服务器的私有地址、密钥或部署配置。

## 7. 待定问题

1. 检查页放在哪里、谁运维。这需要一个公开的 HTTPS 页面，是 Hachi 目前没有的服务端组件，需要维护者决定。
2. 国家或地区数据库用哪一个，多久更新。出口地区本身是根据 IP 推断的，会有误差；文案已经写“出口所在的国家或地区”，不说“你在哪里”。
3. 以后要不要让手机把地区代码通过一次性配对码传回 Mac 自动对照。好处是少一步，代价是要多一个服务端接口和一次性令牌。第一版不做。
4. 手机开着 iCloud 专用代理或运营商代理时，检查页看到的出口可能和应用商店看到的不同。第一版在“查询失败”和帮助文字里提一句，不单独处理。
